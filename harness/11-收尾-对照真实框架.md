# 第 11 章 · 收尾:对照真实框架

> 你现在手里有两套亲手写的系统:`tinycore + tinyharness`(家族 A:循环 + 壳,mini Claude Code)和 `tinygraph + tinyagent`(家族 B:图运行时,深入篇)。这一章不引入新概念,带你站到出口回望:每一块零件对应真实框架的什么、我们刻意砍掉了什么、接下来按什么顺序去读真实源码、以及一份按性价比排序的练习清单。读完这章,框架对你不再是黑盒,而是"我写过的那个东西的工业加厚版"。

## 11.2 对照 Claude Code / Claude Agent SDK(家族 A 正主)

逐模块对表。左列是你写的,右列是生产版多出来的厚度:

| 我们的 | Agent SDK / Claude Code 的 | 生产版厚在哪 |
|---|---|---|
| `Agent.run()` 事件生成器 | `query()` 异步消息流 | async;partial message 流;多模态 content blocks |
| `toolkit.py` 八件套 | Read/Write/Edit/Bash/Glob/Grep/TodoWrite/WebFetch… | 富 diff 渲染;Jupyter/图片支持;后台 Bash;输出限额策略 |
| `ContextManager.compact()` 单级压缩 | 五级渐进压缩管线 + 服务端 compaction | 预算收缩→snip→microcompact→collapse→auto-compact 逐级降压 |
| `load_memory_files()` | CLAUDE.md 体系(全局/项目/子目录/rules) | 导入语法、frontmatter 规则、企业策略层 |
| `PermissionPolicy` 模式+规则+审批 | permission modes + allow/deny rules + `canUseTool` | 规则语言更富;ML 辅助判断命令危险性;记住"本会话已批" |
| `HookManager` 五时机 | 27 种事件的 hook 管线 | 挂任意 shell 命令;JSON 协议;超时与并发管理 |
| `make_task_tool` | Task 工具 + `.claude/agents/*.md` 子代理 | 子代理独立模型/权限配置;后台任务;成批扇出 |
| `skills.py` 渐进披露 | Agent Skills(SKILL.md) | 技能市场;脚本资源;跨产品(Code/API/Cowork)通用 |
| `MCPServerStdio` | 全传输 MCP 客户端 | HTTP/SSE、OAuth、重连、通知、resources/prompts |
| `Session`(JSONL) | `~/.claude/projects/**.jsonl` + resume/fork | 多会话管理、崩溃恢复细节、跨设备 |
| `Harness` 门面 | SDK 的 `ClaudeSDKClient` / CLI 本体 | 负责承载运行基础设施与产品控制面 |

**我们刻意砍掉的**(按"补上它你就更接近生产"排序):async 化、真 OS 沙箱、多模态消息、provider 重试与退避、流式部分消息(工具参数逐段渲染)、压缩的多级管线、权限的"记住选择"。概念一个没少——这张表右列的每一项,你都能说出它挂在四层的哪一层、走哪条接缝进系统。这就是"能读懂"的定义。

## 11.3 对照 OpenAI Agents SDK / Codex(家族 A 的另一极)

Agents SDK 的四原语,用你的零件逐个翻译:

- **Agent** = 我们的 `Agent`(模型 + 工具 + 指令),外加 `SubagentDef` 的档案化;
- **Handoff** = 一种特殊的 task:不是"派活收结论",而是**把整个对话移交**给另一个 Agent 继续(边界上传的是完整历史,不是任务书——第 8 章那张拓扑表的第三行);
- **Guardrail** = 挂在输入/输出上的校验器,职能 ≈ 我们的 `user_prompt_submit` 钩子 + `after`-类检查,理念同为"硬约束不进内核";
- **Session / Runner** = 我们的 `Session` + `Harness.run()`。

Codex CLI 值得单独一提:**开源(Rust)**,是"沙箱优先"姿态的最佳源码教材——看它的 Seatbelt/bubblewrap 集成,正好补上我们没写的第 4 层防线(第 6 章)。

## 11.4 对照 LangGraph / LangChain 1.x(家族 B 正主)

深入篇的 `tinygraph`/`tinyagent` 与真实框架概念 1:1:超步、版本号、检查点链、中断即存盘、`create_agent`、六钩子中间件——真实版是"同一个概念做厚":delta channels(检查点只存增量,40 倍缩减)、Postgres saver、async、`Send` 动态扇出、`Command(goto)`、内置中间件家族。源码阅读路线(五站,带着你的代码并排读):

1. `langgraph.graph.StateGraph` ↔ 你的 `graph.py`——API 几乎一样,先建坐标系;
2. `langgraph.channels` ↔ 你的 `channels.py`——看 `LastValue`/`Topic`/`BinaryOperatorAggregate` 如何扩展合并语义;
3. `langgraph.pregel` ↔ 你的 `pregel.py`——找 plan/execute/commit 三段和版本号触发,其余是工程包裹;
4. `langgraph.checkpoint.*` ↔ 你的 `checkpoint.py`——interface/memory/sqlite 三层看序列化与 pending writes;
5. `langchain.agents.create_agent` + `middleware` ↔ 你的 `tinyagent`——确认它就是"图上搭环 + 洋葱钩子"。

## 11.5 其余主流,一句话定位

- **Microsoft Agent Framework**(AutoGen+SK 合并):家族 B 形态,图 + Actor 双模型,Azure 生态的默认选项。
- **Google ADK**:家族 B 形态,分层 agent 树 + workflow 原语,绑 Vertex/Gemini 生态。
- **CrewAI**:角色化多智能体(crew)+ 流程(flow),原型友好;生产复杂度上来后通常迁向两大正主。
- **Pydantic AI**:类型安全优先的循环框架,"FastAPI 感"的开发体验,家族 A 偏库形态。
- **smolagents**(HF):CodeAct 路线——模型不发 JSON 工具调用,直接写 Python 代码当动作;是"工具调用协议"的激进替代方案,值得读它反思 tool-calling 的边界。
- **Vercel AI SDK**:TS 生态的 L0+L1,v7 的 HarnessAgent 干脆把 Claude Code/Codex 当可插拔后端——"元 harness"趋势的代表。

## 11.6 评测:怎么知道你的 harness 是好是坏

第 0 章关于"同模型换 harness 会产生明显差异"的判断反过来就是你的机会:壳的每一处改进都可能直接提升任务完成率。工程上把评测拆两层,对应我们早已分开的两样东西:

- **机制层**:确定性行为,零模型成本。主线示例用 FakeModel 手工复现——权限该拦的拦住了吗?崩溃后重放合法吗?压缩切点安全吗?
- **能力层**:真模型 + 真任务 + 可验证结果(测试通过?文件正确?),抽样跑、盯趋势。业界基准(SWE-bench 家族、Terminal-Bench)本质就是"给定 harness,统计任务完成率"——你也可以为自己的场景造十个带断言的小任务,那比任何公开榜单都更能指导你的下一行代码。

方法论一句话:**机制用断言钉死,能力用任务度量;前者保证不倒退,后者指引往哪走。**

## 11.7 练习清单(按性价比排序)

1. **async 化 tinycore**(第 4 章预告的第一顺位):`run()` 改 async generator、线程池改 `asyncio.gather`。收获:生产形态 + 对"IO 密集"有体感。
2. **token/成本预算**(第 6 章):harness 层消费 `turn_end`,超限 `interrupt()` 并注入"请收尾总结"。二十行,立刻可用。
3. **Stop 钩子强制续跑**(第 7 章):RUN_END 后 fire STOP,被 block 就带理由重新 `run()`——"活没干完不许停"。
4. **权限加固**:deny 类规则整体优先于 allow;"记住本会话已批准的同类调用"(治审批疲劳的另一半)。
5. **后台子代理**(第 8 章):task 的同步等待改 future + 完成事件,主代理先干别的。
6. **OS 沙箱**(第 6 章第 4 层):用容器跑 bash 工具(docker run 包一层),体会"圈死后 yolo 也安全"。
7. **HTTP 传输 MCP + resources**(第 9 章):客户端骨架直接可扩。
8. **长期记忆**:`after run` 提取事实写入 `(namespace,key)` 存储,启动时注入——对照 R7 的 Store 与向量检索。
9. **深入篇全套练习**(R7 末尾):`Command(goto)`、节点级重试、delta channels——图路线的加厚。

每完成一个,回到 11.2/11.4 的对照表划掉一行"生产版厚在哪"——那张表就是你的进度条。

## 11.8 结语:框架会过时,这两张地图不会

这份教程没有教你任何一个框架的 API——它带你把 2026 年两大家族的**问题与解法**各亲手走了一遍:

- 循环路线教会你:模型即 Agent,工程价值在壳——上下文、权限、会话、扩展点,四层各就各位,层间只隔一条事件流和一个 gate。
- 图路线教会你:状态与控制流可以从进程里取出来,变成可存档、可并行、可回溯的数据——超步之间的空隙是一切能力的插入点。

框架名字会换,SDK 会改版,但"状态放哪、控制流谁定、恢复到什么粒度、约束落在哪一层"这四个问题不会消失——任何新框架发布,你现在都能在十分钟内把它拆进这两张地图里,说出它在哪些取舍上站了哪边。

这就是造过轮子的人看轮子的方式。去读真实源码吧——这一次,你带着自己的实现进去。
